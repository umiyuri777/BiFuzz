## Architecture map to complete during discovery

The first read-only audit must populate these sections with file and symbol references.

### Runtime entry points

- Scene bootstrap and transitions: `StartButtonAction` opens `Game`; `HowToPlayButtonAction` and `BackButtonAction` manage the menu flow; `GameQuit` and `QuitButtonAction` end the application.
- Player control and navigation: `PlayerScript` handles direct movement, collection, and interaction; `PlayerNav` toggles navigation control. `CanvasScript` places the navigation destination. These are coupled to the `FreeLook Camera`, `NavON`, `NavDestination(Clone)`, Player tag, and Cinemachine v2.
- Item collection and game-state management: `Item`, `Damager`, `TestSheep`, `ClearJudgement`, and the Visual Scripting `SheepCounter` asset control entities and clear-state presentation.
- UI and input: `CanvasScript`/`CanvasScript1`, `MiniMapZoom`, and the button-action scripts. `CanvasScript` and `CanvasScript1` are near-duplicate implementations and require serialized-reference auditing before consolidation.
- Persistence and experiment logging: `Assets/Test/Param_Mutate`, `Param_PS_V1`, and `Param_PS_Random` write CSV data under `Assets/Logs` and use PlayerPrefs for mutation state.

### BiFuzz integration

- StarCollection-to-BiFuzz call sites: BiFuzz MonoBehaviours share Player, Cinemachine, scene-reload, and `Assets/Logs` conventions with the StarCollection experiment scripts.
- Shared inputs and outputs: CSV files include `fuzz.csv`, `init_fuzz.csv`, `param_global.csv`, `param_local.csv`, `check_points.csv`, `detected_bugs.csv`, `fuzz_type.csv`, and position/timing logs; these formats are behavior-critical.
- Fuzz selection, initialization, local search, and position-management responsibilities: `fuzz_select` enables either `grad_init` or `grad_local`; `grad_init` performs global/initial exploration; `grad_local` performs local exploration and mutation; `PositionLogger` records positions.
- Timing/measurement responsibilities: `ExeTime` persists elapsed-time information.

### Test map

- EditMode tests: none discovered by Unity Test Framework on 2026-09-03.
- PlayMode tests: none discovered by Unity Test Framework on 2026-09-03.
- Reproduction scenes and manual smoke-test paths: `Assets/Test/` contains MonoBehaviour-based experiment and replay components, not registered Test Framework tests. `Game` Play Mode is the current minimal smoke-test path; generated `InitTestScene*.unity` files must be regenerated by their owning flow.
